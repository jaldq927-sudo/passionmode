SCENE 2

JAVA_HOMEとPATH

PATH は受付の座席表
PATHコマンドを上から探す一覧
JAVA_HOMEどのJDKを使うかのメモ

座席表に無いと「'mvn' は認識されていません」。

① 設定画面を開く
スタート「環境変数」で検索
環境変数の編集システム／アカウント
［環境変数］ボタン

ここで JAVA_HOME と Path を触る。

② JAVA_HOME を新規作成
ダメC:\Program Files\Java\jdk-17\bin
→
OKC:\Program Files\Java\jdk-17

JDKのフォルダそのもの。\bin は付けない。JREは不可。

③ Path にbin を追加
%JAVA_HOME%\bin      ← 新規で追加
%MAVEN_HOME%\bin     ← Mavenの展開先\bin
C:\old\java8\bin     ← 古いJavaは下へ

上にある方が使われる。［上へ］で新しい方を上に。

④ 窓を開き直す
コマンドプロンプト開いていた窓には反映されない
IDE も再起動古い設定のまま動く

setx より画面で編集する方が安全。

⑤ mvn -v で確認
> mvn -v
Apache Maven 3.9.x
Java version: 17.0.x, runtime: C:\Program Files\Java\jdk-17①
1Mavenが使うJDKはここ。想定どおりか見る

java -version が17でも、Mavenは8のことがある。

SCENE 4

settings.xmlの3か所

置き場所：C:\Users\名前\.m2\settings.xml（自分で作る）

<!-- URL・ID はダミー。実際の値は社内で確認 -->
<mirror><id>company-nexus</id>①
  <url>https://nexus.example.co.jp/repository/maven-public/</url>
  <mirrorOf>*</mirrorOf></mirror>
<server><id>company-nexus</id>②
  <username>…</username><password>…</password></server>
<proxy><host>proxy.example.co.jp</host><port>8080</port>③
  <nonProxyHosts>localhost|*.example.co.jp</nonProxyHosts></proxy>
1mirrors：行き先を社内Nexusへ振り替え
2servers：入館証。id を①と同じに
3proxies：外へ出る門。社内は門を通さない
id が1文字違うと 401大文字・ハイフンも区別される
読めたか確認mvn help:effective-settings
SCENE 5

証明書エラー（PKIX）

# 管理者で実行（JDK 9以降）。社内CAのファイルは社内で入手
keytool -importcert -cacerts -alias corp-root-ca -file C:\certs\corp-root-ca.cer -storepass changeit

登録先は mvn -v の runtime のJDK（JDKごとに別）。

SCENE 6

エラーを押して調べる

'mvn' は認識されていません

  • 意味：OSがmvnを見つけられない
  • 原因：PathにMavenのbinが無い
  • 直し方：Pathに追加→窓を開き直す

JAVA_HOME … not defined correctly

  • 意味：Mavenが使うJDKが無い
  • 原因：未設定・末尾に\bin・JREを指す
  • 直し方：JDKのフォルダそのものを指す

Could not resolve dependencies

  • 意味：必要な部品を取れなかった
  • 原因：下に本当の理由（401等）が続く
  • 直し方：続きと Caused by を読む

401 Unauthorized

  • 意味：Nexusに入れてもらえない
  • 原因：パスワード誤り・id不一致
  • 直し方：serverとmirrorのidを揃える

403 Forbidden

  • 意味：入れたが見る権限がない
  • 原因：閲覧権限なし・URL違い
  • 直し方：URL確認→管理者に権限依頼

407 Proxy Authentication Required

  • 意味：プロキシの認証に失敗
  • 原因：proxiesのユーザー名等が無い
  • 直し方：proxiesの認証を確認

PKIX path building failed

  • 意味：接続先の証明書を信用できない
  • 原因：社内CAがcacertsに無い
  • 直し方：mvn -v のJDKにkeytoolで登録

invalid target release

  • 意味：指定の版でコンパイルできない
  • 原因：Mavenが古いJDKで動いている
  • 直し方：JAVA_HOMEを指定JDKへ

Connection timed out

  • 意味：相手に届かない
  • 原因：mirror未設定でCentralへ直行
  • 直し方：ホスト名を見てmirror確認

QUIZ

タップで答え合わせ

JAVA_HOME に …\jdk-17\bin。何がダメ？
\bin は不要。bin まで書くのは Path の方。
repo.maven.apache.org でタイムアウト。まず疑うのは？
mirrorが効いていない。settings.xml が読めているか確認。
401 と 407 の違いは？
401＝Nexusで拒否（servers）。407＝門のプロキシで拒否（proxies）。
keytoolで登録したのにPKIXが消えない
別のJDKに入れた可能性大。mvn -v の runtime のJDKに登録する。
