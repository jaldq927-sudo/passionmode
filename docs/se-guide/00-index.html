12章の地図

下から順に積み上がる構造です。土台の「技術の地図」がわかると、上の「現場の仕事」をAIに任せきりにせず、自分で判断できるようになります。

おすすめの読み方

  1. 01 を読む（20分）不安の正体を整理して、何を目指すかを決めます。
  2. 05 に取りかかる（最優先）4か月止まっている開発環境を、まず動かします。ここが動けば、残りの章を自分のPCで試せます。わからない箇所は、05章の「先輩に確認するリスト」をそのまま使って質問してください。
  3. 02 → 03 → 04 → 06 で土台をつくる毎日30分、実際のソースとDBを見ながら読みます。
  4. 07・08・09 は仕事が来たときに開く障害調査、申請XML、改修依頼が来たら、その章の手順に沿って自分で進めてから、AIに確認させます。
  5. 10・11 は毎日少しずつAIの使い方と伝え方は、毎日の仕事で練習できます。
  6. 12 で進み具合を確認する月に1回、チェックリストで自分の成長を確認します。

このガイドについて

会社ごとに違う部分（社内リポジトリのURL、申請XMLのタグ名、サーバ構成など）は「一般的な例」として書いています。各章の「先輩・社内Wikiに確認する項目」を使って、自分の現場の答えに置き換えてください。それ自体が、システムを理解する一番の近道です。
