ログと障害調査

最初の1件を探す
一番下のCaused byを読む
問い合わせ時刻≠発生時刻
SCENE 1

ログの地図

ブラウザ利用者
Apache受付
Tomcat作業場
アプリSpring Boot
PostgreSQL保存

層ごとに別のログ。押して、何が書かれるか見よう。

Apache

  • access_log＝受付台帳
  • 誰が・いつ・何に・結果は
  • 影響範囲を数えるのに使う

Tomcat

  • catalina.out：標準出力・OOM
  • catalina.日付.log：起動・配備
  • localhost.日付.log：初期化失敗

アプリ

  • 開発者が書いたログ
  • 例外とスタックトレース
  • なぜ失敗したかを探す

PostgreSQL

  • SQLのエラー
  • デッドロック・接続数超過
  • 遅いSQL（設定したとき）

JVM（GCログ）

  • メモリ掃除の回数と停止時間
  • メモリ不足の前ぶれ
  • 起動オプションで出す設定

置き場所は構成で変わる。実物の場所は先輩に聞いてメモ。

ログ1行を分解する

ERROR処理が失敗

平常時のWARNを知っておくと「いつもと違う」に気づける。

SCENE 3

アクセスログは受付台帳

本当は1行。項目ごとに分けて表示（Apache combined＋%D）。

10.20.31.45                        ① IP
- -                                    ユーザー（通常は空）
[12/Mar/2026:09:03:41 +0900]       ② 時刻
"POST /kintai/clock/in HTTP/1.1"   ③ 何の機能
500                                ④ ステータス
1243                                   返したバイト数
"https://…/kintai/top" "Mozilla/…"     参照元・ブラウザ
30215871                           ⑤ 処理時間
1プロキシ経由だとプロキシのIP
2応答ではなく、受け付けた時刻
3メソッドとURL
4下のタイルで意味を見る
5Apacheはマイクロ秒 → 約30.2秒
2xx成功（3xxは転送）
4xx利用者側（404など）
5xx500アプリ失敗／502・503裏につながらない／504裏が時間切れ

Tomcatの既定には処理時間が無い。%Dの単位も版で違う。

SCENE 5

よくある障害7つ

メモリ不足

  • 症状 じわじわ重く→無応答
  • 証拠 OOM・Full GC多発
  • 対処 再起動は応急。原因処理を特定

コネクション枯渇

  • 症状 30秒ほど待って500
  • 証拠 Connection is not available
  • 対処 返らない原因（遅SQL等）を解消

スレッド枯渇

  • 症状 静的ページも遅い・502/503
  • 証拠 処理時間が全体に伸びる
  • 対処 待っている先を解消

ロック待ち

  • 症状 特定の更新だけ固まる
  • 証拠 wait_event_type = Lock
  • 対処 ブロック元を特定（06章）

ディスクフル

  • 症状 突然書けない・ログが途切れる
  • 証拠 No space left on device
  • 対処 手順どおり退避・ローテーション

外部連携タイムアウト

  • 症状 連携する処理だけ遅い
  • 証拠 SocketTimeoutException
  • 対処 相手先に確認・再送手順

起動失敗

  • 症状 直後から全画面404/503
  • 証拠 APPLICATION FAILED TO START
  • 対処 一番下のCaused by→切り戻し判断
再起動で直った≠解決原因が残れば、また起きる
SCENE 6

調査は7コマで進む


1. 時刻と症状を確定
あいまい朝、打刻できないらしい
→
確定3/12 9:03ごろ、打刻画面で500

2. 前後の出来事を並べる

リリース・設定変更・バッチ・締め日・外部メンテ


3. アクセスログで範囲

500は何時から何件？どのURL？全画面か一部か


4. 最初のERRORを探す

少し前から読む。後半のエラーは巻き添えが多い


5. 根本原因へ

Caused by・自社コード・DBの状態。「なぜ」を2〜3回


6. 影響を数える

どの機能・どのデータ・何人。登録漏れや二重登録は？


7. 再発防止

修正だけでなく、検知（監視）と手順も直す

SCENE 7

本当の始まりはいつ？

「9:10発生」と書くと、9:02〜9:10の人を見落とす。

架空の例：締めバッチのロックで打刻が待たされ、接続が枯渇。

SCENE 8

巨大ログはコマンドで

# 流れてくるログを見る
tail -F /opt/tomcat/logs/catalina.out
# 例外の行＋後ろ30行（スタックトレース）
grep -n -A 30 'SQLTransientConnectionException' app.log | less
# 圧縮した古いログも数える
zgrep -c 'OutOfMemoryError' catalina.out-20260311.gz
# ステータス500の件数（combined形式は9番目）
awk '$9 == 500' access_log | wc -l
# 500が出たURLの上位
awk '$9 == 500 {print $7}' access_log | sort | uniq -c | sort -rn | head
REM 例外名を含む行（/N 行番号）
findstr /N /C:"OutOfMemoryError" catalina.2026-03-12.log
# PowerShell：流れてくるログを見る
Get-Content .\app.log -Wait -Tail 50
# 例外の行＋後ろ30行
Select-String -Path .\app.log -Pattern 'SQLTransientConnectionException' -Context 0,30
# ステータス500の件数
(Select-String -Path .\localhost_access_log.2026-03-12.txt -Pattern '" 500 ').Count
トレースは日時なし時刻で絞ると消える。原因はgrep -Aで読む
日またぎ・.gz前日のファイルと圧縮済みも見る
文字化けしたらSelect-String -Encoding UTF8
