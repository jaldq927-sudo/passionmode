Java・Spring・WAR・JAR

Javaは言葉、Springは骨組み
業務ルールは自社のJavaコード
WARもJARも中身はzipの箱
前半業務ルールはどこにある？
SCENE 1

登場人物は3人いる

Java と Spring Boot と
自社のコードは別もの

Java言葉（日本語のようなもの）
Spring BootJavaで書かれた骨組み
自社のコードJavaで書いた業務ルール

業務ルールは3人目にあります。Spring Bootは、それを動かす土台です。

SCENE 2

家づくりでたとえると

骨組み（Spring Boot）はどの会社でも同じ。勤怠らしさは間取りと家具（自社コード）にあります。

SCENE 3

勤怠アプリの断面図

緑の層だけが「あなたの会社の勤怠システム」。下は全部、借りてきた部品です。

SCENE 4

1つのクラスを3色に塗る

同じファイルの中に、3人の持ち物が混ざっています。

@Service                                   // Spring：「部品として用意して」
public class OvertimeService {            // Java：クラスの書き方

  @Transactional                           // Spring：「全部成功か全部取消」
  public Duration calc(AttendanceRecord r) { // Java：メソッド
    Duration work = Duration.between(r.getIn(), r.getOut());
    if (work.compareTo(Duration.ofHours(8)) > 0) {   // ルール：8時間を超えたら
      return work.minusHours(8);                    // ルール：超えた分が残業
    }
    return Duration.ZERO;
  }
}
Spring（@で始まる印）Java（言葉そのもの）業務ルール（自社が決めた中身）
@ の行Springへのお願い。消すと動かないが、ルールではない
黄色の行就業規則がコードになった所。改修はここが多い

説明用に簡略化した例です。実際の残業計算は休憩・深夜・休日などがあり複雑です。

SCENE 6

業務ルールの置き場所は5つ

Javaだけではありません。押して、場所と探し方を見てください。

Serviceクラス

  • 例：8時間超は残業、22時以降は深夜
  • 場所：…/service/〇〇Service.java
  • 探す：grep -rn "深夜" src/

SQL

  • 例：締め済みの月は除く WHERE 条件
  • 場所：resources/mapper/*.xml
  • 探す：テーブル名や列名で grep

マスタ・設定テーブル

  • 例：所定労働時間8時間、締め日15日
  • コードを変えずに値だけ変えられる
  • 探す：SELECT で中身を見る

設定ファイル

  • 例：バッチの実行時刻、機能のON/OFF
  • 環境ごと（本番・検証）に違う値
  • 探す：*.properties / *.yml

申請定義XML

  • 例：通勤費は課長→人事の順に承認
  • 入力必須・文字数の制限
  • 詳しくは 08章

SCENE 9

WARもJARも、中身はzip

JAR = Java ARchiveJavaのファイルを詰めた箱
WAR = Web ARchiveWebアプリ1本分を詰めた箱

「書類をまとめたzip」と同じ。拡張子で用途を区別しているだけです。

SCENE 10

お弁当でたとえると

ライブラリのJAR市販の冷凍食品（おかず1品）
WARお弁当一式。食堂のレンジで温める
実行できるJAR紐を引くと温まる加熱式駅弁
Tomcat食堂の電子レンジ

違いは「Tomcatが外にあるか、中にあるか」。入れ子が逆になります。

SCENE 11

WARの中を開けてみる

ファイル名を押すと、それが何かが出ます。緑が自社、紫が他人の部品です。

kintai.war

  • 勤怠アプリ1本分の箱
  • mvn package で作られる
  • Tomcatの webapps/ に置く

WEB-INF/

  • アプリの本体が入る場所
  • ブラウザから直接は見えない

classes/（自社）

  • 自社の .java をコンパイルした .class
  • com/会社名/kintai/…Service.class
  • 業務ルールはここ。設定ファイルもここ

lib/（部品）

  • spring-core-x.x.jar などが数十〜百個
  • postgresql-x.x.jar（DBにつなぐ部品）
  • 社内共通の部品jarもここに入る

web.xml

  • Tomcatへの説明書
  • Spring Boot製なら無いこともある

META-INF/

  • 箱のラベル（MANIFEST.MF）
  • 作成ツールや版の情報

css/ js/ images/

  • 画面の見た目のファイル
  • ブラウザがそのまま受け取る
SCENE 12

WARとJAR、中身を比べる

kintai.war
├─ WEB-INF/
│   ├─ classes/   ← 自社のコードと設定
│   ├─ lib/       ← 部品jar（Spring など）
│   └─ web.xml
└─ css/ js/

# 動かし方：Tomcat の webapps/ に置く
kintai.jar
├─ BOOT-INF/
│   ├─ classes/   ← 自社のコードと設定
│   └─ lib/       ← 部品jar ＋ Tomcat本体のjar
├─ META-INF/MANIFEST.MF
└─ org/springframework/boot/loader/

# 動かし方：java -jar kintai.jar
postgresql-42.x.jar
├─ org/postgresql/Driver.class
├─ org/postgresql/…（たくさん）
└─ META-INF/MANIFEST.MF

# 単体では動かない。アプリが中で使う部品

自社の部分（classes）と部品（lib）に分かれる形は、3つとも同じです。

SCENE 13

「部品のリスト」は半分正解

会社のWARやJARって、よく使う機能のフレームワークのリスト？

半分正解です。WARの中の lib/ は、まさに部品のリストです。

でも classes/ には自社の業務ルールが入っています。WARは「アプリ本体＋部品セット」です。

サーバで見かける3種類の箱

自社アプリ

kintai.war
shinsei.war

業務ルール入り。改修するとここが変わる

社内共通の部品

company-common.jar
xx-auth-lib.jar

複数のシステムで使い回す自社製の部品

世の中の部品

spring-core-x.x.jar
postgresql-x.x.jar

Spring・DBドライバなど。誰でも使える

ファイル名は一般的な例です。自社の名前は実際のサーバで確かめてください。

SCENE 14

本当の部品リストは pom.xml

<!-- pom.xml の一部（例） -->
<packaging>war</packaging>   ← WARで作るか JARで作るか
<dependency>
  <groupId>org.postgresql</groupId>
  <artifactId>postgresql</artifactId>   ← 部品の名前
</dependency>

「よく使う部品のリスト」の正体は pom.xml の dependency です。
