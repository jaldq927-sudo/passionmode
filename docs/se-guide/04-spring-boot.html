Spring Bootの正体

自分のコードは「呼ばれる側」
部品は備品係が机に置く（DI）
受付→判断→書庫の3層で分担
SCENE 1

呼ぶ側？呼ばれる側？

ライブラリ自分が呼ぶ。
LocalDate.now()
vs
フレームワークSpringに呼ばれる。
URLが来たら打刻メソッドを実行

どこからも呼ばれないのに動く＝Springが呼んでいる。

URLが来た@GetMapping
時刻になった@Scheduled
起動した@PostConstruct

探すのは「誰が呼ぶか」より「呼ばれる条件」。

SCENE 2

DIは「備品係」

部品を自分で new すると…

自分で作ると、Springの管理から外れる。

備品係が机に置いてくれる

起動時にコンテナが部品（Bean）を作って渡す。

書き方はコンストラクタで
@Service
public class OvertimeService {
  private final OvertimeMapper mapper;①
  public OvertimeService(OvertimeMapper mapper) {②
    this.mapper = mapper;
  }
}
1final＝途中で入れ替わらない
2引数＝欲しい部品の一覧。newは書かない

@RequiredArgsConstructor があれば、この形を自動で作る。

SCENE 3

3層を押して確かめる

Controller

  • 役目：URLを受け、入力の形をチェック
  • 目印：@RestController
  • バグ：引数名違いでnull・GET/POST違い

Service

  • 役目：業務ルールで判断する
  • 目印：@Service @Transactional
  • バグ：条件漏れ・例外の握りつぶし

Repository / Mapper

  • 役目：SQLを実行して返すだけ
  • 目印：@Mapper＋XMLのSQL
  • バグ：WHERE条件・NULL・< と <=

DB（PostgreSQL）

  • 役目：データを保存し、制約で守る
  • 目印：timecard などのテーブル
  • バグ：一意制約違反・桁あふれ・遅い

ログのクラス名の末尾（…Service）で、どの層か見当がつく。

SCENE 4

@ラベル辞典

@は「こう扱ってね」とSpringに伝える付箋。

@SpringBootApplication起動クラス。この下をスキャン
@RestControllerJSONを返す入口
@GetMapping @PostMappingURLとメソッドを結ぶ（取得／操作）
@PathVariableURLの {id} を受け取る
@RequestParam?month=… の値を受け取る
@RequestBodyJSON本文をオブジェクトで受け取る
@Service業務ロジックの部品（Bean）にする
@MapperMyBatisのSQL（XML）とつなぐ
@TransactionalDB更新をひとまとめ。失敗で取り消し
@Value設定ファイルの値を入れる
@Scheduled決まった時刻に実行。cronは秒からの6項目
@Autowiredここに部品を注入して
SCENE 5

全部か、ゼロか

付けないと「承認済みなのに履歴なし」が残る。

チェック例外は戻らないIOException等は rollbackFor が必要
catchで握りつぶすと確定外へ投げないとCOMMITされる
同じクラス内呼び出しthis.xxx() だと効かない
SCENE 6

起動の流れ

main@SpringBoot​Application

Bean生成スキャン→注入

SCENE 7

SQLはどこにある？

pom.xmlspring-boot-starter-data-jpa
目印@Entity・JpaRepository
SQLの場所基本なし。自動生成→ログで見る
pom.xmlmybatis-spring-boot-starter
目印@Mapper のインターフェース
SQLの場所resources 配下の Mapper XML
<!-- TimecardMapper.xml -->
<mapper namespace="…mapper.TimecardMapper">①
  <select id="countToday" resultType="int">②
    SELECT COUNT(*) FROM timecard
     WHERE employee_id = #{employeeId}
  </select>
</mapper>
1インターフェースの完全名と一致
2メソッド名と一致。値は #{} で安全に
pom.xmlspring-boot-starter-jdbc
目印JdbcTemplate のフィールド
SQLの場所Javaコードの中の文字列

@Mapper や @Entity を全文検索すれば数分でわかる。

SCENE 8

設定は環境で上書き

application.properties共通の土台
application-local.propertieslocalで上書き
spring.profiles.active=local①
spring.datasource.url=jdbc:postgresql://localhost:5432/kintai
server.port=8080
1local なら -local の方で同じキーを上書き

本番だけ動かない時は「どのプロファイルで起動？」から。
