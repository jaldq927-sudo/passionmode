システムの全体像

5つの層がリレーしている
ログは層ごとに別の場所
症状から「どの層か」を絞る
SCENE 1

レストランで考える

お客さんブラウザ
受付係Apache
厨房Tomcat
料理人とレシピSpring Boot
食料庫PostgreSQL

お客さんに厨房は見えない。「料理が来ない」の原因はどこにでもある。

SCENE 2

5つの層を押してみる

ブラウザ

  • 画面を描き、ボタンで送信
  • 見る所：F12 の Network

Apache

  • https を受ける・画像を返す
  • アプリ宛ては Tomcat へ
  • ログ：access_log error_log

Tomcat

  • Java アプリを動かす入れ物
  • 1件ごとにスレッドを割当
  • ログ：catalina.out

Spring Boot

  • 会社の業務ルールそのもの
  • Controller→Service→DB
  • ログ：kintai.log など

PostgreSQL

  • 打刻・社員データを保存
  • SQL で出し入れする
  • ログ：postgresql-*.log

ログのパスは一般例。自分の現場の場所は先輩に確認。

SCENE 4

行きと帰りは同じ道

数字はポート番号（窓口の番号）の一般例。

SCENE 5

返事の番号を色で見る

200 OK成功。一覧が出た
302 移動打刻後に完了画面へ
404 ないURLの打ち間違い・未配備
403 権限なし一般社員が承認画面へ
500 内部エラーアプリの例外。アプリログへ
503 / 502 / 504Apache が奥と話せない

緑＝成功、黄＝頼み方の問題、赤＝サーバ側の問題。

SCENE 7

ログが無いのも手がかり

無い＝そこまで届いてないかも。手前の層は？

Apache の access_log を同じ時刻で探します

サーバが2台なら両方ね。再起動で直っても原因は残るよ

SCENE 8

WARとJARは入れ子が逆

$ ps -ef | grep java
... org.apache.catalina.startup.Bootstrap start

これが見えたら WAR の可能性大。設定は server.xml。

$ ps -ef | grep java
... java -Xmx2g -jar /opt/kintai/kintai.jar

これなら JAR。設定は application.properties。

QUIZ

タップで答え合わせ

朝9時、全員の画面に 503。まず疑う層は？
Tomcat。止まっていないか、起動完了したかを catalina.out で見る。
1人だけ打刻で 500。どこを見る？
アプリログのスタックトレース。その人のデータ特有の状態を疑う。
ロゴ画像 logo.png を返すのは誰？
Apache。誰が見ても同じ「静的ファイル」は受付が直接返す。
ps に Bootstrap start が出た。WAR？JAR？
WAR。外部の Tomcat が動いている印。
